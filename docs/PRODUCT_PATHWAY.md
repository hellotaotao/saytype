# SayType 产品路径与当前工作清单

更新：2026-09-25。问题清单按 1.15.10 之后的 `main`（含删除翻译 `9d90904`、发布改为先草稿 `7007aab`）重新核对。本文是当前产品优先级入口；旧设计文档保留历史依据，不自动代表待实施需求。线上发布状态不由本文件背书。

## 产品与范围

SayType 是本地优先的桌面语音输入工具。维护者已经每天将它作为主力甚至唯一输入方式；当前任务不是再验证个人需求，而是降低维护负担，并验证其他人能否自行持续使用。

核心承诺：按键说话、松手得到文字；失败明确可见，已取得的内容尽可能可恢复。完整音频覆盖、识别内容准确、目标应用收到文字是三个不同的验收项目。

- 保留 Qwen 与 Nemotron，两种引擎共享任务生命周期规则，保留各自批量/实时协议。Nemotron 识别率明显不如千问，但它是唯一的真实时转写（边说边出字）；这是现有其他引擎给不了的，所以暂时保留，不当作待删项再提。
- 保留主动选择的云端转写。本地失败不应静默上传云端。
- 翻译（Shift+Alt 转成英文）用得太少，2026-09-25 已整体删除（`9d90904`），连同它的服务商选择和上传同意流程。
- 当前先不增加第三种模型家族、会议工作台、知识库或 Agent 工作流。1.15.0 加入的 Qwen3-ASR 1.7B 是千问的另一个尺寸，作为实验选项提供，默认仍是 0.6B。
- 不整体重写。遇到具体生命周期问题时，逐步分离任务管理、采集、引擎适配、恢复和 UI。

## 首次引导与引擎政策（2026-09-14）

- 引导顺序为欢迎 → 隐私 → 引擎 → 麦克风 → 辅助功能 → 练习；非 macOS 不显示辅助功能步骤。用户主动选择下载后，模型可在授权期间后台下载；下载完成只更新就绪状态，不覆盖后来选择的引擎。
- 千问 0.6B 为首选。只有检测到内存低于 8 GiB 或逻辑核心少于 4 时，新配置默认 OpenAI；检测失败仍默认千问。已有配置和旧配置的缺字段兼容规则不变。
- Apple M4 且内存至少 16 GiB 时，引导并列展示 1.7B 的耗时、内存和下载量对比；M5 及以上同样突出展示。推荐标记和本地默认型号始终留在 0.6B，1.7B 准确率尚未实测。其余机器把 1.7B 放进更多选项，Windows 分级等待目标机器测量。
- OpenAI 是本地性能不足时的云端选择；Groq 和 Nemotron 收进引导的更多选项。设置页保留完整引擎列表，v1.15.8 起点整行即可切换；首页引擎列表也保持平铺。首页只显示千问、OpenAI 和“更多”的想法记在 TODO #15，暂不做。
- 选择与就绪分开：模型没下载完也能选本地，但录音前必须提示完成模型设置。练习框只在引擎与所需权限就绪时出现；下载中可以继续授权步骤。
- 每段录音的普通听写及自动重试按开始时的 provider 路由，切换设置不会把后续分块改传云端。显式从 History 重转录仍使用当前引擎。
- 向导可暂时收起以进入设置，再从原步骤继续。浏览器模拟、macOS 编译和单元测试不替代新用户账户、Windows 与真实目标输入验收。

## 平台承诺

| 平台 | 维护方向 | 证据边界 |
| --- | --- | --- |
| macOS | 主要支持目标；原生 CoreAudio 采集 | 按设备、系统、麦克风和目标应用记录结果；Apple Silicon 经验不代表 Intel 已验收 |
| Windows x64 | 主要支持目标；保留独立平台验收 | CPU、可选 Vulkan、真实输入分别验证；构建或模型 smoke 不代表全链路已验收 |
| Linux | 实验性安装包与构建检查 | 目前无维护者真机验收；不能承诺各发行版、X11/Wayland 等价可用 |

“主要支持目标”是投入优先级，不是全部配置已验证。README 的平台描述只随具体证据更新。

## 路径与阶段门槛

### A. 可维护的输入系统（现在）

- [x] 核对当前源码基线与近期故障类别，形成本文。
- [x] 验收离线隐私诊断 CLI：逐 session 查看生命周期与分块计数，只输出白名单字段，不导出正文、原始日志、设备名或路径。
- [ ] 下次尾段事故用诊断记录缩小故障区间；必要时用户主动提供音频或文字对照。原始原因仍开放，不提前认定修复。
- [ ] 按 `RELIABILITY_ACCEPTANCE.md` 执行目标设备案例并保存结果。
- [ ] 每个确认的根因都有回归案例；硬件问题保留操作步骤与环境，能模拟的加入自动化。
- [ ] 根据真实问题逐步集中 session 状态控制权；先提取并测试一个边界，不在本轮改全链路。

退出条件：已复现的 P0 有证据支持的修复和回归；未复现的 P0 保留明确状态、恢复方式及取证路径。未解决的数据丢失问题阻止扩大推广，而不是阻止继续调查。

### B. 小范围可复制的产品（A 的基础具备后）

- 招募前先写好试用反馈表（原引导评审 F-004，草稿见 [TRIAL_FEEDBACK.md](TRIAL_FEEDBACK.md)）：只问卡在哪一步、用了多久、看到哪些权限弹窗、下载是否顺利、一周后是否还在用，不收听写内容。
- 招募 5–10 名自愿用户，覆盖 Mac/Windows、高频输入和中英混合；邀请与分发由维护者决定，本轮不联系任何人。
- 首次安装不给现场指导，记录第一次成功输入之前的阻碍与所需帮助。
- 一周后记录是否继续使用、为何退回其他输入方式、恢复是否需要找维护者。
- 汇总支持成本：每人需要帮助次数、定位耗时、恢复动作；样本小，保留人数与分母，不写成市场结论。
- 不要求提交正文或录音；诊断先由用户预览，内容样本另行同意。

退出条件：多数参与者能自行完成首次输入并持续使用；阻碍重复出现时先解决对应问题，再扩大人数。具体人数、结果与例外必须记录。

### C. 个人化输入（B 提供修正证据后）

只选择一个高频修正类别试验：用户明确添加的专有词汇/中英混合术语优先。比较同一组获得授权的样本，记录修正次数和新引入的内容错误；不自动收集其他应用内容，也不默认学习纠错。

退出条件：选定人群的修正动作确实下降，且没有增加静默内容错误。效果不成立就撤回，不为路线图硬加功能。

### D. 是否商业化（可复制与支持成本已有证据后）

再决定继续个人项目、开放社区支持或收费。依据持续使用、实际支持负担及付费意愿，不预设账户系统、订阅、同步或云服务建设。商业化前另行评估许可证与依赖约束。

## 发布与决策纪律

- 采集、runtime、调度或输入改动：除自动测试外，记录受影响的真实设备验收；紧急修复列明跳过项及原因。
- 实验构建先明确分发给愿意测试的人；没有独立稳定/实验更新通道之前，不声称通道已实现。
- 不以 `insert/complete` 计算端到端成功率。人工确认的输入结果与程序事件分开。
- 维护工作指标：已确认故障的复发次数、每次定位所需时间；输入体验指标：需补救次数/已观察听写次数，以及按设备/引擎划分的松手后等待。
- 功能进入下一阶段前回答：它减少哪类真实修正、重试或配置成本？如何验证？会增加哪些维护路径？
